# Prompt-a-thon Build Lab

Status: preparation, 2026-11-13. The event prompt is not yet known. No product idea has been selected. This workspace is isolated from the internship pipeline and other checkouts.

## When the prompt arrives
1. Translate the prompt into a specific user, painful situation, desired outcome and constraints. Confirm judging criteria and time.
2. Generate two or three substantially different concepts; compare user value, how clearly the idea answers the prompt, demo impact and feasibility. Choose with Jatin.
3. Define a three-step demo: concrete starting state, one meaningful user action, and a credible payoff. Identify the riskiest assumption.
4. Build one vertical slice. Use real integration where essential and feasible; label sample data and simulated outcomes honestly.
5. Build, test in a real browser at desktop and mobile widths, check keyboard and reduced motion, and repair the demo path.
6. Rehearse a two-minute pitch: problem, live demonstration, why it matters, and a prompt-design insight supported by actual experiments.

## Design direction
Choose the visual direction to suit the eventual product and audience. Prioritize clear hierarchy, distinctive typography, coherent spacing and color, useful states, and one memorable interaction. Avoid placeholder text and decoration that obscures the task.

## Starting stack
React + TypeScript + Vite for a quick interactive prototype. Add Tailwind or shadcn/ui only where they speed up the actual UI; add a backend only when the core interaction needs it. Use native CSS for simple transitions and Motion for interactions that justify it.

## Boundaries
Do not publish, submit, contact people, alter the internship pipeline, or store credentials in this repo. Preserve the event prompt and actual results once known. No claims that canned output is live AI.

## Working loop
1. Choose the user, problem, one demo moment, and what is out of scope.
2. Plan the next slice: goal, constraints, observable success, and how to verify it.
3. Build the slice; delegate independent work only when the benefit justifies the cost.
4. Verify with appropriate checks and test the actual product interaction in a real browser.
5. Record what works, what remains uncertain, and the next decision in a short status note when useful.
6. Repeat, stopping feature work early enough to rehearse the pitch.
