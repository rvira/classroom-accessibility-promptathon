# Build Lab working rules

Build one small, testable product slice. Read brief.md and relevant source files before editing. Use descriptive names and keep dependencies purposeful. Preserve unrelated projects and user data. Do not publish, submit, contact people, or commit secrets. Verify user-facing changes in a real browser when available; report limitations and distinguish live functionality from examples. Explain consequential choices in plain language.

## Delegation
Jatin authorizes Ares to choose when to use available subagents: delegate bounded, independent tasks when the expected gain in speed or review quality justifies context and coordination cost; keep small or sequential work local. Assign clear outputs and separate write scopes, integrate and verify results, and explain material token tradeoffs. Follow the active session's actual delegation permissions and limits.

## Project workflow
For each meaningful slice, record the goal, constraints and observable acceptance checks. Implement a cohesive slice and verify the actual user journey in a browser where applicable. Keep a concise current-state/next-steps note when useful; check the code and tests as the source of truth. Scale documentation to project complexity.
